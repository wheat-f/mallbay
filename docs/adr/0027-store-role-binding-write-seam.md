# 门店角色绑定变更由统一写入 seam 承担

建店、成员邀请与移除、换店长及手工权限治理保留各自的业务流程，但所有门店范围角色绑定变更通过同一 module 执行；总部绑定与角色 grant 的策略发布不归入该 seam，总部绑定变化仍须递增同一用户授权版本。这样成员关系、实际变化的每条绑定、审计、绑定变更标识的结果与用户授权版本可以随业务状态在同一事务提交，提交后的权限读取不依赖缓存过期来识别撤权。

有效绑定仍是访问权依据：普通岗位信息变更不自动修改绑定；权限治理可以明确授予非成员门店绑定；成员离店时停用其原门店全部绑定。`MANAGER` 绑定只能随建店或换店长流程变更，换任后的新店长只保留该店的 `MANAGER` 绑定，成功提交的门店恰有一名店长；重复的同一业务意图返回原结果，冲突的旧状态或复用标识但改变内容的请求失败。

写入 interface 采用受限的声明式领域计划：业务流程在 module 持有的事务内写自身事实，并返回离店、入店、授权、停用或替换角色等动作；module 统一兑现绑定、逐条审计、业务摘要、持久命令结果和用户授权版本。HTTP 写入调用必须提供稳定的 `X-Request-Id` 作为绑定变更标识；同一标识的重试不得重复执行业务 callback，事务提交后的外部通知须使用去重键。

上线前预检阻止已有多名店长或成员缺少任何有效本店绑定的情况，但不要求普通成员的角色与岗位同名；非成员的显式门店绑定只报告来源供核查，不自动撤销或补授。若无法核对持久的用户授权版本，受保护请求拒绝使用旧缓存结果。此决定延续 ADR-0019、ADR-0020 和 ADR-0023 对有效绑定、策略发布及岗位信息的既有所有权约束。
