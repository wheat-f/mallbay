## 4. 复评检查结果

### 4.1 范围与目标

- 系统标签与人工标签分离，系统标签后端统一派生，人工标签复用客户编辑权限。
- 非目标已排除标签字典、独立标签权限、营销画像和客户分群运营，范围边界清晰。
- 不改变客户归属、负责人和数据范围规则，避免引入无关业务变更。

### 4.2 规则与状态

- 新客户：无已完成订单；老客户：至少 1 个已完成订单；二者互斥。
- 已完成订单明确对应尾款结清后系统自动标记的 `COMPLETED` 状态。
- 价值等级按已完成订单 `paidAmountCents` 累计，5,000 元为高价值、10,000 元为 VIP，只显示最高等级。
- 重点关注原因和 30 个自然日的北京时间边界已定义；前三类来源可实施，投诉/服务异常在无统一数据源时不产生误标签。
- 标签顺序、原因、阈值合法性和闭环移除规则均已明确。

### 4.3 权限、数据范围与审计

- 查看、编辑权限沿用现有客户权限模型；后端仍是最终裁决。
- 总部阈值配置限定为 `settings.write.GLOBAL`，带版本校验和审计。
- 人工标签新增/删除、失败结果、门店范围和操作人均要求留痕。
- 客户所属门店作为统计范围，客户转移沿用既有规则。

### 4.4 接口与前端

- `systemTags` 与 `customTags` 分离返回，系统标签包含 `code`、`label`、`level`、`reasons`。
- 列表和详情返回同名字段，兼容字段不得重复计算。
- 系统标签固定编码筛选，人工标签按 ID 筛选；筛选由服务端完成并返回真实总数。
- 前端删除旧的本地标签推导逻辑，只展示后端结果；详情展示重点关注触发原因。

### 4.5 异常与验收

- 已覆盖无完成订单、并发删除、历史重名、非法阈值、系统计算失败和无投诉数据源等边界。
- 验收标准包含规则、权限、接口一致性和业务事件刷新场景，具备转测试用例的条件。
- 未设置虚构的业务指标目标；指标列为待补充，不阻塞功能研发。

## 5. 非阻塞实施跟踪项

1. 财务数据治理：核查退款或红冲是否始终回写 `OrderAmount.paidAmountCents`，异常数据记录告警并补修。
2. 投诉/服务异常：若要启用第四类重点关注原因，需补充统一数据模型、状态和闭环事件；在此之前保持不生成该原因。
3. 缓存方案：研发可选择首期不加缓存；若加缓存，必须遵守 PRD 中的范围、阈值版本和失效约束。
4. 上线后补充指标目标和统计周期。

## 6. 最终结论

评审通过。PRD 已达到研发实施所需的业务规则、数据口径、权限边界、接口结构、交互要求、异常处理和验收标准完整度，可以进入研发评审和任务拆解。
