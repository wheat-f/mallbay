# 客户标签体系优化 PRD

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 需求名称 | 客户系统标签与人工标签分离优化 |
| 文档版本 | v1.2 |
| 当前状态 | 评审通过，待研发实施 |
| 创建日期 | 2026-08-03 |
| 关联模块 | 客户管理、订单、财务、售后、质保 |
| 关联材料 | 客户标签方案评审结论 |

## 2. 需求背景

### 2.1 业务背景

当前客户列表展示“新客户、老客户、高价值客户”等标签，但这些标签由后端和前端分别计算，判断标准不一致；同时，人工标签与系统派生标签在页面上混合展示，用户无法判断标签来源，也难以找到人工标签维护入口。

### 2.2 当前问题

1. “老客户”同时存在按车辆数量和按订单数量判断的逻辑。
2. “新客户”同时存在按创建时间和按订单数量判断的逻辑。
3. “高价值客户”同时存在按客户类型和按消费金额判断的逻辑。
4. 前端存在本地补算标签逻辑，可能覆盖或补充后端结果，造成列表与详情不一致。
5. 系统标签与人工标签共用“客户标签”展示区域，无法区分自动标签和人工标签。
6. 系统标签没有明确展示触发原因。
7. 历史人工标签可能与系统标签重名，存在重复展示风险。

## 3. 产品目标

- 建立系统标签与人工标签完全分离的客户标签体系。
- 由后端统一计算系统标签，前端只负责展示，不再自行推导。
- 统一新老客户、价值等级和重点关注的判断口径。
- 为人工标签提供清晰、可发现、可审计的维护入口。
- 保留历史人工标签，避免升级造成数据丢失。
- 让客户列表和客户详情使用同一套标签接口结果。

## 4. 非目标

本期不包含：

- 不建设总部统一人工标签字典。
- 不新增独立的客户标签权限模型。
- 不允许用户手工修改系统标签的状态或触发原因。
- 不删除历史人工标签数据。
- 不改变客户归属、客户负责人或客户数据范围规则。
- 不在本期扩展复杂的客户画像、自动营销和标签分群运营能力。

## 5. 用户角色与权限

沿用现有客户模块权限模型：

| 角色/权限 | 查看系统标签 | 查看人工标签 | 新增人工标签 | 删除人工标签 | 数据范围 |
|---|---:|---:|---:|---:|---|
| 具备客户查看权限的用户 | 是 | 是 | 否 | 否 | 沿用客户查看范围 |
| 具备客户编辑权限的用户 | 是 | 是 | 是 | 是 | 沿用客户编辑范围 |
| 销售 | 是 | 是 | 是 | 是 | 仅负责客户 |
| 店长 | 是 | 是 | 是 | 是 | 本门店客户 |
| 总部管理员 | 是 | 是 | 是 | 是 | 按现有总部数据范围 |

系统标签始终只读。人工标签新增、删除必须经过现有客户编辑权限校验，并记录审计信息。

## 6. 核心业务对象

| 对象 | 定义 | 关键字段/来源 | 状态或生命周期 |
|---|---|---|---|
| 客户 | 门店客户主数据 | 客户 ID、门店、负责人、客户类型、车辆、订单 | 按现有客户模型 |
| 系统标签 | 由客户业务数据派生的只读标签 | `code`、`label`、`level`、`reasons` | 不单独维护，不物理落库 |
| 人工标签 | 用户主动添加到客户的标签 | 标签 ID、客户 ID、名称、创建人、创建时间 | 新增、保留、删除 |
| 已完成订单 | 尾款结清后由系统标记为完成的订单 | 订单状态、实收金额 | 作为新老客户和价值标签的统计依据 |
| 重点关注原因 | 触发重点关注标签的业务事项 | 尾款、售后、质保、投诉/服务异常 | 原因产生、持续、闭环 |


### 6.1 数据统计范围

- 系统标签按客户记录所属的 `customer.storeId` 统计，不跨门店合并订单、金额、售后或质保数据。
- 总部管理员查看多个门店客户时，每个客户仍按其所属门店独立计算。
- 客户转移门店后，转移生效后的查询按新门店范围计算；历史统计是否随客户迁移重算由现有客户转移规则决定，本需求不新增迁移机制。
## 7. 系统标签规则

### 7.1 新客户与老客户

| 标签 | 条件 | 系统动作 |
|---|---|---|
| 新客户 | 客户没有任何已完成订单 | 返回 `NEW_CUSTOMER` |
| 老客户 | 客户至少存在 1 个已完成订单 | 返回 `OLD_CUSTOMER` |

规则说明：

- “已完成订单”沿用现有订单规则：尾款结清后，系统自动标记为“已完成/最终交付”。
- 报价中、施工中、待尾款、售后处理中等订单不计为已完成订单。
- 新客户与老客户互斥，不能同时返回。
- 新客户原因固定为“暂无已完成订单”；老客户原因固定为“存在已完成订单”。
- 系统标签返回顺序固定为：客户阶段（新客户/老客户）→价值等级（VIP或高价值）→重点关注。
- 车辆数量、客户类型、客户创建时间不得参与新老客户判断。

### 7.2 价值等级

| 等级 | 默认累计实收金额 | 标签 | 展示规则 |
|---|---:|---|---|
| 普通 | 小于高价值阈值 | 无价值等级标签 | 不展示高价值等级 |
| 高价值 | ≥ 5,000 元 | `HIGH_VALUE` | 达到 VIP 后不再单独展示 |
| VIP | ≥ 10,000 元 | `VIP` | 只展示 VIP |

规则说明：

- 只统计客户所属门店下已完成订单的实收金额。
- 首期以客户所属门店下、订单状态为 `COMPLETED` 的订单对应 `OrderAmount.paidAmountCents` 累计作为实收金额，金额单位为分，按 `>=` 阈值比较后换算为元展示。
- `paidAmountCents` 已按现有结算/冲销流程维护；首期不另行拼接独立退款流水，若退款或红冲未回写该字段，不得静默计入或扣减，必须记录数据异常并进入财务数据修复流程。
- 未结清尾款的订单不计入累计实收金额。
- 高价值阈值默认 5,000 元，VIP 阈值默认 10,000 元；VIP 阈值必须大于高价值阈值。
- 总部管理员在系统设置中配置阈值，使用现有 `settings.write.GLOBAL` 权限、版本校验和审计；门店用户不可修改。
- 系统只返回最高等级标签；VIP 客户不同时展示“高价值客户”。
- 价值标签原因必须包含实际统计金额和当前阈值，例如“累计已完成订单实收金额 12,000 元，达到 VIP 阈值 10,000 元”。
- 阈值调整后，客户系统标签按新阈值重新计算，不修改历史订单金额。

### 7.3 重点关注客户

客户满足任一条件时返回 `KEY_FOLLOW_UP`：

1. 存在未结清尾款；
2. 存在未关闭的售后单；
3. 存在 30 个自然日内到期的有效质保；
4. 存在待处理投诉或服务异常记录。

时间边界按北京时间计算：质保到期时间大于等于当前时间，且小于当前时间加 30 个自然日，视为“30 天内到期”。

当对应事项全部闭环后，系统不再返回“重点关注客户”。同一客户存在多个原因时全部返回，原因顺序固定为：尾款、售后、质保、投诉/服务异常。

重点关注标签可以与新客户、老客户或 VIP 标签同时返回。系统必须返回具体触发原因，例如：

- `存在未结清尾款`
- `存在未关闭售后单`
- `质保将在 30 天内到期`
- `存在待处理服务异常`

v1 以现有尾款、售后和质保数据实现前三类触发。投诉/服务异常仅在研发确认已有可查询、可判断闭环状态的数据源后启用；若当前没有统一数据源，v1 不生成该原因，作为后续扩展，不阻塞前三类上线。

## 8. 人工标签规则

### 8.1 基本规则

- 人工标签由具备客户编辑权限的用户在客户详情页新增或删除。
- 保存前去除首尾空白；去除首尾空白后为空则拒绝，重复判断也基于去除首尾空白后的名称；内部空格按用户输入保留。
- 标签名称允许自由输入，最大长度 30 个字符。
- 标签名称不能为空或仅包含空格。
- 同一客户不能重复添加相同名称的人工标签。
- 人工标签不参与系统标签计算。
- 人工标签删除不影响系统标签。
- 新增人工标签时，禁止使用系统标签保留名称：
  - 新客户
  - 老客户
  - 高价值客户
  - VIP 客户
  - 重点关注客户
- 历史人工标签即使与系统标签重名，也不物理删除。

### 8.2 历史重名标签

- 历史人工标签继续保留数据库记录和审计记录。
- 接口可返回历史人工标签，但展示层按名称去重。
- 如果系统标签和历史人工标签同名，页面只显示一个名称，并优先标识为系统标签。
- 新增人工标签命中系统保留名称时，接口返回明确错误，不创建数据。

### 8.3 审计

人工标签新增和删除必须记录：

- 客户 ID；
- 标签 ID或标签名称；
- 操作类型；
- 操作人；
- 操作时间；
- 门店范围；
- 请求结果。

## 9. 接口需求

### 9.1 客户列表和详情返回结构

客户列表和客户详情统一返回以下字段：

```ts
{
  systemTags: Array<{
    code: "NEW_CUSTOMER" | "OLD_CUSTOMER" | "HIGH_VALUE" | "VIP" | "KEY_FOLLOW_UP";
    label: string;
    level: "CUSTOMER_STAGE" | "VALUE" | "WARNING";
    reasons: string[];
  }>;
  customTags: Array<{
    id: string;
    label: string;
    createdBy?: string;
    createdAt: string;
  }>;
}
```

接口要求：

- `systemTags` 必须由后端根据当前业务数据计算。
- `customTags` 必须来自人工标签数据。
- 列表行和详情响应均直接提供同名的 `systemTags`、`customTags` 字段；详情内已有的 `archiveSummary.systemTags` 在兼容期可只读镜像，但不得与新字段分别计算，兼容期结束后移除旧字段。
- 两者不得通过同一个数组混合返回。
- 系统标签必须返回触发原因；客户阶段、价值等级和重点关注均必须有可展示原因。无原因的系统标签视为接口错误。
- `systemTags` 最多返回 3 个，顺序固定为客户阶段、最高价值等级、重点关注；`customTags` 返回当前数据范围内的全部记录，超出列表展示空间时由前端折叠并显示剩余数量。
- 前端不得根据车辆数量、客户类型或创建时间再次推导系统标签。
- 历史重名人工标签由前端展示去重，接口仍保留原始记录。

### 9.2 人工标签操作

沿用现有客户标签接口：

- `POST /customers/tags`：新增人工标签；
- `DELETE /customers/tags/:id`：删除人工标签。

新增接口校验：

- 无客户编辑权限：返回 403；
- 标签为空：返回参数错误；
- 超过 30 个字符：返回参数错误；
- 同一客户重复标签：返回冲突错误；
- 命中系统标签保留名称：返回冲突错误；
- 客户不存在或已不在当前数据范围：返回 404 或 403。


### 9.3 列表筛选与分页

- 系统标签筛选参数使用固定编码，例如 `systemTag=VIP`、`systemTag=KEY_FOLLOW_UP`。
- 人工标签筛选参数使用人工标签 ID；多个条件时采用“任一人工标签命中”规则，具体接口参数名由研发按现有客户列表查询规范确定。
- 系统标签和人工标签同时筛选时，采用 AND 关系：客户必须满足系统标签条件且命中人工标签条件。
- 筛选在后端执行，不能只在当前页数据上由前端过滤。
- 列表分页、排序和客户数据范围沿用现有客户列表接口；筛选后的总数必须反映真实匹配结果。
- 系统标签筛选必须使用与返回结果相同的派生规则和固定编码；人工标签筛选按 `CustomerTag.id` 查询，不得按展示名称模糊匹配。
## 10. 页面与交互

### 10.1 客户列表

入口：客户管理列表页。

页面规则：

- 将现有“客户标签”拆分为“系统标签”和“人工标签”两列。
- 系统标签展示新老客户、最高价值等级和重点关注状态。
- 人工标签展示用户创建的自由标签。
- 系统标签和人工标签提供独立筛选条件。
- 系统标签筛选选项来自固定系统标签集合。筛选采用编码匹配，不能按展示文案模糊匹配。
- 人工标签筛选选项来自当前数据范围内的人工标签集合。人工标签筛选采用“任一选中标签命中”规则。
- 列表不显示重复标签。
- 系统标签可展示简短原因提示；完整原因在详情页查看。
- 客户无系统标签或人工标签时，分别显示对应空状态。

### 10.2 客户详情

入口：客户列表操作栏“查看”或点击客户名称。

页面规则：

- 客户详情顶部展示系统标签。
- 系统标签只读。
- 点击“重点关注客户”可查看当前触发原因和关联业务事项。
- “客户标签”区域只维护人工标签，并明确标注“人工标签”。
- 有客户编辑权限时显示新增和删除操作。
- 无编辑权限时仅展示人工标签，不显示新增/删除操作。
- 添加成功后刷新人工标签区域和列表缓存。
- 删除成功后刷新人工标签区域，并保留审计记录。

## 11. 标签刷新机制

系统标签不单独落库，采用后端实时派生方式。以下事件发生后必须让后续列表/详情查询立即得到最新结果：

| 事件 | 影响标签 |
|---|---|
| 订单尾款结清并自动完成 | 新客户/老客户、价值等级 |
| 订单状态变为已完成 | 新客户/老客户、价值等级 |
| 售后单关闭 | 重点关注 |
| 质保状态或到期时间变化 | 重点关注 |
| 尾款结清 | 重点关注 |
| 投诉或服务异常处理完成 | 重点关注 |
| 总部调整价值阈值 | 价值等级 |

实现要求：

- 业务事件完成后清理客户标签查询缓存；若首期不启用缓存，则直接查询最新数据，不以缓存作为正确性前提。
- 若启用缓存，缓存键至少包含客户 ID、门店数据范围和阈值版本；业务事件、客户门店转移、阈值发布后必须失效相关缓存，失效失败需记录告警并在读取时校验版本。
- 同一事件重复消费不得产生重复标签。
- 事件处理失败不得修改人工标签。
- 系统标签计算失败时接口返回可识别错误，不返回过期的前端自行计算结果。

## 12. 数据与字段

| 字段 | 含义 | 类型 | 来源 | 规则 |
|---|---|---|---|---|
| `systemTags` | 系统派生标签 | 数组 | 后端实时计算 | 只读，不单独落库 |
| `systemTags[].code` | 系统标签编码 | 枚举 | 后端 | 不允许前端修改 |
| `systemTags[].label` | 系统标签名称 | 字符串 | 后端 | 统一中文展示 |
| `systemTags[].level` | 标签维度 | 枚举 | 后端 | 客户阶段/价值/预警 |
| `systemTags[].reasons` | 触发原因 | 字符串数组 | 业务数据 | 所有系统标签必须有原因 |
| `customTags` | 人工标签 | 数组 | `CustomerTag` | 与系统标签分离 |
| `customTags[].label` | 人工标签名称 | 字符串 | 用户输入 | 必填，最长 30 字符 |
| `customTags[].createdBy` | 创建人 | 用户 ID/名称 | 当前登录用户 | 只读展示 |
| `customTags[].createdAt` | 创建时间 | 时间 | 系统 | 只读展示 |
| `highValueThreshold` | 高价值阈值 | 金额 | 总部配置 | 默认 5,000 元 |
| `vipThreshold` | VIP 阈值 | 金额 | 总部配置 | 默认 10,000 元，必须高于高价值阈值 |

## 13. 状态与规则变化

系统标签不是独立状态，不允许人工切换。标签结果由业务数据变化自动变化：

| 当前结果 | 触发事件 | 新结果 |
|---|---|---|
| 新客户 | 首个订单尾款结清并完成 | 老客户 |
| 普通客户 | 累计已完成订单实收金额达到高价值阈值 | 高价值客户 |
| 高价值客户 | 累计金额达到 VIP 阈值 | VIP 客户 |
| 重点关注 | 尾款、售后、质保或异常未闭环 | 继续保留并更新原因 |
| 重点关注 | 所有触发事项闭环 | 移除重点关注 |

人工标签只有新增和删除，不受系统标签状态变化影响。

## 14. 异常与边界情况

| 场景 | 系统处理 | 用户反馈 |
|---|---|---|
| 客户无已完成订单 | 返回新客户 | 正常展示 |
| 客户同时满足高价值和 VIP | 只返回 VIP | 不显示高价值客户 |
| 客户同时满足新/老客户条件 | 以已完成订单结果为准，新老客户互斥 | 正常展示 |
| 重点关注存在多个原因 | 返回全部当前原因 | 详情页逐项展示 |
| 人工标签与系统标签同名且为历史数据 | 保留数据，展示去重 | 标识优先显示系统标签 |
| 新增人工标签命中保留名称 | 拒绝创建 | 提示该名称为系统标签 |
| 重复新增人工标签 | 拒绝创建 | 提示标签已存在 |
| 系统标签计算失败 | 接口返回错误，不由前端兜底计算 | 页面展示加载/错误状态 |
| 并发删除同一人工标签 | 只有首次成功，后续返回不存在或幂等结果 | 页面刷新标签列表 |
| 价值阈值配置非法 | 拒绝保存 | 提示 VIP 阈值必须高于高价值阈值 |
| 投诉/服务异常无统一数据源 | 先接入已有三类重点关注来源，第四类进入技术评估 | 不展示无法确认来源的标签 |

## 16. 验收标准

### 16.1 系统标签

- Given：客户没有任何已完成订单；When：查询客户列表和详情；Then：返回 `NEW_CUSTOMER`，不返回 `OLD_CUSTOMER`。
- Given：客户存在 1 个已完成订单；When：查询客户列表和详情；Then：返回 `OLD_CUSTOMER`，不返回 `NEW_CUSTOMER`。
- Given：客户只有施工中或待尾款订单；When：查询客户标签；Then：这些订单不计入新老客户判断。
- Given：客户累计已完成订单实收金额为 12,000 元；When：查询标签；Then：只返回 `VIP`，不返回 `HIGH_VALUE`。
- Given：客户有未结清尾款；When：查询标签；Then：返回 `KEY_FOLLOW_UP`，原因包含未结清尾款。
- Given：尾款结清且其他重点关注事项均已闭环；When：再次查询标签；Then：不再返回 `KEY_FOLLOW_UP`。

### 16.2 人工标签

- Given：用户具备客户编辑权限；When：在客户详情页新增合法人工标签；Then：创建成功并记录审计。
- Given：用户不具备客户编辑权限；When：调用新增或删除标签接口；Then：返回 403，数据不变。
- Given：人工标签名称与系统标签保留名称相同；When：提交新增；Then：创建失败并提示不可使用系统标签名称。
- Given：历史人工标签与系统标签同名；When：查询列表和详情；Then：数据库记录保留，页面不重复展示。
- Given：用户删除人工标签；When：删除成功；Then：人工标签消失，系统标签不受影响。

### 16.3 前后端一致性

- Given：客户存在任意业务数据；When：分别查询客户列表和客户详情；Then：`systemTags` 使用相同编码、等级和触发原因。
- Given：订单尾款结清；When：系统完成订单状态更新后重新查询客户；Then：系统标签使用最新已完成订单结果。
- Given：前端未加载标签计算逻辑；When：查询客户；Then：后端仍能返回完整系统标签，前端只负责展示。
