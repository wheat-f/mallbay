# 基础字典分层配置与逐项启停实施方案

**文档状态：** 一期已落地，后续按本计划持续完善
**适用范围：** 系统设置、产品管理、销售订单、采购管理、施工管理、财务相关字典
**目标角色：** 店长、总部管理员、财务、销售、施工人员

## 1. 背景与问题

当前基础字典页面将系统固定字典、门店自定义值和启用状态混为一体，导致：

1. 产品分类、施工类型等字典无法新增门店业务所需的小类。
2. 启用/禁用只能定位到整个字典，不能定位到单个字典项。
3. 系统字典项与门店自定义项没有区分，新增时统一被后端拒绝。
4. 保存后页面显示成功，但重新打开又恢复旧数据，无法确认是否真正写入服务端。
5. 平铺字典无法表达“大类—小类”关系，业务选择器也无法按层级过滤。

## 2. 实施目标

本次改造完成后应满足：

- 系统基础编码受到保护，不能被误删或改码。
- 店长可在允许的字典中新增门店自定义项和小类。
- 每个字典项可独立启用、禁用、恢复。
- 支持大类与小类的树形关系。
- 保存结果以服务端数据为准，刷新、重新登录后仍保持一致。
- 已被业务单据引用的字典项只能停用，不能物理删除。
- 历史单据保留原始字典快照，不因后续维护而被改写。
- 所有新增、修改、启停、删除动作均产生审计记录。

## 3. 业务规则

### 3.1 字典来源

| 来源 | 说明 | 可删除 | 可改编码 | 可停用 |
|---|---|---:|---:|---:|
| 系统内置 | 系统发布的基础编码 | 否 | 否 | 按字典策略 |
| 总部模板 | 总部下发给门店的模板项 | 否 | 否 | 按门店策略 |
| 门店自定义 | 店长为本门店新增的项目 | 未引用时允许 | 编码不可改 | 是 |

### 3.2 启用/禁用

- 启用/禁用必须针对单个字典项。
- 字典整体状态仅表示该字典功能是否开放，不替代字典项状态。
- 父级禁用时，子级在新业务选择器中不可选；子级配置不删除。
- 子级禁用不影响其他兄弟项。
- 禁用后不影响历史订单、采购单、库存流水和已保存草稿的历史显示。
- 草稿引用了已停用项时，提交前提示更换；历史正式单据不要求更换。
- 不允许停用字典中最后一个可用的必选项。

### 3.3 删除

- 系统内置项和总部模板项禁止删除。
- 门店自定义项只有在未被任何业务数据引用时才能删除。
- 已引用项统一改为停用，不执行物理删除。
- 删除、停用均要求记录操作原因。

### 3.4 编码

- 编码由服务端生成或校验，前端不得自行拼接最终编码。
- 系统编码永久不可修改。
- 门店自定义编码自动生成，例如 `STORE_BJ_0001`。
- 同一字典、同一父级下编码和名称均不得重复。

## 4. 数据模型改造

### 4.1 Dictionary

新增或确认以下字段：

| 字段 | 说明 |
|---|---|
| `code` | 字典编码，如 `PRODUCT_CATEGORY` |
| `name` | 字典名称 |
| `source` | `SYSTEM`、`HQ_TEMPLATE`、`STORE` |
| `allowCustomItems` | 是否允许门店新增 |
| `allowDisableItems` | 是否允许逐项停用 |
| `allowHierarchy` | 是否允许父子层级 |
| `status` | 字典整体启用状态 |
| `version` | 乐观锁版本号 |
| `updatedBy/updatedAt` | 最后修改信息 |

### 4.2 DictionaryItem

新增或确认以下字段：

| 字段 | 说明 |
|---|---|
| `id` | 字典项主键 |
| `dictionaryId` | 所属字典 |
| `parentId` | 父级字典项，可为空 |
| `code` | 业务编码，创建后不可修改 |
| `label` | 显示名称 |
| `source` | 系统、总部、门店 |
| `status` | `ACTIVE`、`INACTIVE` |
| `sortOrder` | 显示顺序 |
| `usageCount` | 引用次数，可实时统计或异步维护 |
| `disabledReason` | 停用原因 |
| `createdBy/createdAt` | 创建信息 |
| `updatedBy/updatedAt` | 修改信息 |

约束：

- 唯一约束：`dictionaryId + parentId + code`。
- 名称约束：`dictionaryId + parentId + normalizedLabel`。
- `parentId` 不得形成循环引用。
- 删除前必须检查订单、采购、库存、施工和客户车辆等引用关系。

## 5. 页面实施方案

### 5.1 字典列表页

列表增加：

- 字典来源。
- 是否允许新增。
- 是否支持小类。
- 启用项数/停用项数。
- 最后保存时间。
- 最后操作人。

### 5.2 字典维护弹窗

将当前“多输入框 + 底部统一状态”的形式改为树形维护面板。

页面结构：

1. 字典基本信息区：名称、编码、来源、维护策略。
2. 搜索和筛选区：名称、编码、状态、来源。
3. 字典项树形列表。
4. 新增字典项/新增小类按钮。
5. 保存状态和服务端刷新按钮。

每一行展示：

| 层级 | 名称 | 编码 | 来源 | 引用次数 | 状态 | 操作 |
|---|---|---|---|---:|---|---|
| 大类 | 膜类 | `FILM` | 系统 | 25 | 启用 | 停用 |
| 小类 | 漆面保护膜 | `PPF` | 系统 | 18 | 启用 | 停用 |
| 小类 | TPU | `STORE_BJ_0001` | 门店 | 0 | 启用 | 编辑、删除 |

每个字典项独立显示启停控件，禁止使用弹窗底部的全局状态控件。

### 5.3 新增字典项

表单字段：

- 所属父级，可选；
- 名称，必填；
- 编码，系统项只读，门店项默认自动生成；
- 排序号；
- 初始状态，默认启用；
- 备注/业务说明。

如果当前字典不允许新增，按钮不显示或置灰，并直接说明“该字典只允许总部维护”。

### 5.4 保存反馈

保存流程必须具备：

- 未保存修改提示；
- 保存按钮显示提交中状态；
- 服务端返回成功后才显示成功提示；
- 返回新增项真实 `id/code`；
- 成功后自动重新拉取服务端数据；
- 清理前端查询缓存；
- 部分成功时逐项显示结果；
- 失败时保留输入内容，不得伪造成功状态。

## 6. 接口设计

```text
GET    /settings/dictionaries/{code}?tree=true&includeDisabled=true
POST   /settings/dictionaries/{code}/items
PATCH  /settings/dictionaries/{code}/items/{itemId}
POST   /settings/dictionaries/{code}/items/{itemId}/enable
POST   /settings/dictionaries/{code}/items/{itemId}/disable
DELETE /settings/dictionaries/{code}/items/{itemId}
```

### 6.1 新增请求示例

```json
{
  "parentId": "item-film",
  "label": "TPU",
  "sortOrder": 10,
  "reason": "门店新增产品分类"
}
```

### 6.2 并发控制

所有更新请求携带字典版本号或 `If-Match`：

```text
客户端版本：v3
服务端当前版本：v4
结果：409 DICTIONARY_VERSION_CONFLICT
```

冲突时前端提示“字典已被其他人员修改，请重新加载后再保存”，不得覆盖他人的修改。

### 6.3 事务要求

新增、修改、启停、删除必须在同一事务内完成：

1. 权限校验；
2. 字典策略校验；
3. 唯一性和层级校验；
4. 引用关系校验；
5. 写入字典项；
6. 更新版本号；
7. 写入审计日志；
8. 返回最终服务端记录。

## 7. 权限设计

| 操作 | 店长 | 总部管理员 | 财务 | 销售 | 施工人员 |
|---|---:|---:|---:|---:|---:|
| 查看字典 | 是 | 是 | 是 | 是 | 是 |
| 新增门店项 | 是 | 是 | 否 | 否 | 否 |
| 编辑名称/排序 | 是 | 是 | 否 | 否 | 否 |
| 启用/禁用 | 是 | 是 | 否 | 否 | 否 |
| 删除未引用自定义项 | 是 | 是 | 否 | 否 | 否 |
| 修改系统编码 | 否 | 否 | 否 | 否 | 否 |
| 查看审计记录 | 是 | 是 | 是 | 只读 | 只读 |

门店采用独立生效模式：店长维护只影响当前门店；总部模板发布后，由门店选择是否接收或覆盖未自定义的模板项。

## 8. 业务系统联动

字典项状态必须由服务端统一过滤，不能仅依赖前端隐藏。

- 新建销售订单：只返回启用的客户类型、车型、产品分类、产品单位。
- 新建采购单：只返回启用的供应商类型、采购单位和付款类型。
- 施工标准：只返回启用的施工类型和施工地点。
- 库存管理：历史批次保留原单位和分类名称。
- 财务、发票、报表：历史单据按快照展示，不因字典项改名而改变历史数据。

## 9. 迁移计划

### 阶段一：数据补齐

- 为现有字典项补齐 `source`、`status`、`parentId`、`version`。
- 现有系统字典项统一标记为 `SYSTEM`。
- 现有门店新增项按门店归属回填为 `STORE`。
- 所有现有项默认启用，避免影响现有业务。

### 阶段二：策略配置

首批配置：

| 字典 | 允许门店新增 | 支持小类 | 允许逐项停用 |
|---|---:|---:|---:|
| 产品分类 | 是 | 是 | 是 |
| 施工类型 | 是 | 是 | 是 |
| 产品单位 | 按总部策略 | 否/可配置 | 是 |
| 付款类型 | 是 | 否 | 是 |
| 收款账户类型 | 是 | 否 | 是 |
| 质量检查结果 | 否 | 否 | 按总部策略 |
| 售后责任 | 是 | 否 | 是 |

### 阶段三：灰度发布

建议顺序：

1. 收款账户类型；
2. 付款类型；
3. 产品分类；
4. 施工类型；
5. 其他业务字典。

## 10. 测试与验收

### 功能验收

- 新增门店小类后刷新页面仍存在。
- 新增项出现在新建订单选择器中。
- 单独禁用一个小类，其他小类仍可选。
- 禁用父类后，子类不可选但配置仍保留。
- 系统编码不能修改或删除。
- 已引用项只能停用。
- 未引用门店自定义项可删除。
- 保存后退出、重新登录、切换门店数据仍正确。

### 数据验收

- 数据库存在新增字典项真实主键和编码。
- 页面列表与接口返回一致。
- 前端缓存清理后不会回显旧数据。
- 历史订单中的字典快照不发生变化。
- 审计日志记录操作人、门店、前后值、时间和原因。

### 异常验收

- 重复名称返回明确错误。
- 重复编码返回明确错误。
- 父级不存在或形成循环时拒绝保存。
- 并发修改返回版本冲突。
- 无权限用户无法通过接口绕过前端限制。
- 保存失败时不显示成功提示。

## 11. 上线、监控与回滚

### 上线前

- 备份字典表和关联业务数据。
- 执行迁移脚本并核对数量。
- 运行接口、页面和权限回归测试。
- 开启字典配置功能开关但暂不开放全部字典。

### 上线后监控

重点监控：

- 字典新增失败率；
- 字典保存后回读不一致；
- `DICTIONARY_VERSION_CONFLICT` 次数；
- 业务选择器加载空数据；
- 禁用项仍被新单据选中的情况。

### 回滚

- 关闭新字典维护功能开关；
- 保留已产生的审计日志；
- 不删除新增数据，避免破坏已创建的业务单据；
- 必要时恢复字典项状态，但不回写历史订单快照。

## 13. 待确认的三个业务开关

本方案默认采用以下设置：

1. 产品分类、施工类型允许店长新增门店自定义小类。
2. 系统基础项允许逐项停用，但不允许删除或改编码。
3. 门店自定义项只在当前门店生效，总部模板作为辅助来源。

如果某个字典不允许上述行为，只需在字典策略中关闭对应开关，不需要再次改页面和接口结构。
