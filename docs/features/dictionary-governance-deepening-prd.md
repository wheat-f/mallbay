# DictionaryGovernance（字典治理）深化 PRD

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 目标 | 将运行时字典与总部模板字典收拢到一个来源无关的治理 module |
| 目标角色 | 总部字典维护人、门店字典维护人、门店运营人员 |
| 设计依据 | `dictionary-governance.service.ts`、`dictionaries.service.ts`、`dictionary-templates.service.ts` |
| 本期原则 | 保留两个真实 adapter；隐藏来源分支；保持现有路由兼容 |

## 2. 背景与目标

当前治理 module 已经同时连接运行时字典和总部模板两个 adapter，但外部仍通过 `kind` 理解来源差异，并在治理 interface 中重复分发目录、条目、导入、状态和删除规则。

本期将来源策略、权限、导入预览/提交、版本并发、状态、删除约束、审计和缓存一致性收拢到 `DictionaryGovernance` module。总部模板导入门店后形成门店自己的可编辑快照，不建立持续继承。

非目标：不改变字典业务含义；不把业务对象状态改造成字典；不允许删除总部模板条目；不新增跨门店同步。

## 3. 核心对象

- 运行时字典：属于具体门店，可编辑，拥有版本、状态和条目。
- 总部模板字典：属于总部，作为只读来源 adapter，可维护模板自身，但模板条目不能删除。
- 门店快照条目：由模板导入后写入门店字典，后续按门店字典规则独立编辑。

## 4. 业务规则

1. 目录读取根据访问主体返回可见的运行时字典和总部模板；调用方不自行拼接来源。
2. 总部模板只能由具备总部能力的访问主体维护；门店主体只能读取可用模板并发起导入。
3. 导入先预览，返回新增、更新、错误和待提交版本；预览不写业务事实。
4. 提交导入必须携带当前版本（如调用方提供），在一个事务内更新条目、递增版本并写审计。
5. 模板导入成功后写入门店自己的字典快照；后续模板变化不得静默改写门店条目。
6. 门店字典条目可按现有规则启停、更新和删除，删除必须有原因并写审计。
7. 总部模板条目不可删除；不以统一 interface 抹平该业务差异。
8. 重复提交同一版本或相同请求不得重复改变条目。

导入时 `code` 是稳定匹配键：已存在 code 进入更新预览，不存在 code 进入新增预览；同一批次重复 code 或父级关系非法时，预览失败且不可提交。

## 5. 权限与数据范围

| 角色范围 | 读取 | 写入 |
|---|---|---|
| 总部治理主体 | 总部模板及可见目录 | 模板创建、更新、启停、条目维护 |
| 门店治理主体 | 本店字典、可用模板目录 | 本店字典及条目、模板导入 |
| 无对应 capability | 不可读取或写入 | 拒绝且不泄露来源存在性 |

## 6. 异常与边界

| 场景 | 结果 |
|---|---|
| 来源标识无效 | 明确拒绝，不进入 adapter |
| 模板不存在或不可用 | 导入拒绝，不写门店条目 |
| 导入条目 code 重复 | 预览报告错误，提交不可执行 |
| 版本冲突 | 拒绝提交，要求重新预览 |
| 模板条目删除 | 明确拒绝并保持数据不变 |
| 门店条目删除无原因 | 校验失败，不写入 |
| 审计失败 | 业务事务回滚 |
| 缓存失效失败 | 记录可观测错误，不能让旧缓存绕过版本结果 |

## 7. interface 与 seam 约束

- 对外 interface 表达“目录、条目、预览、提交、状态、删除”等治理意图，不要求调用方分支处理来源。
- 运行时字典和总部模板是两个内部 adapter；来源差异只在 module 内部解释。
- controller 不直接调用 `DictionariesService` 或 `DictionaryTemplatesService` 完成治理写入。
- contract test 通过治理 interface 验证两个 adapter 的共同规则和来源特有规则。
- 现有 `kind=dictionary/template` 只作为兼容输入，由 controller adapter 映射到来源无关 interface；新 module 内部不得再按路由参数分支。
- 统一返回结构保留 `readOnly`、`inherited`、来源和能力事实，避免隐藏模板只读差异。

## 8. 验收标准

- Given 门店主体可读取一个总部模板，When 执行预览导入，Then 只返回变更摘要，不改变门店条目。
- Given 预览版本仍有效，When 提交导入，Then 条目、版本、审计一次性完成。
- Given 模板后续更新，When 查看已导入门店字典，Then 门店快照不被静默改写。
- Given 门店字典条目删除缺少原因，When 提交删除，Then 操作被拒绝且条目仍存在。
- Given 总部模板条目，When 尝试删除，Then 明确拒绝且无删除审计。
- Given 两个提交者使用同一字典版本，When 后者提交，Then 后者收到并发冲突且不得覆盖前者。
- Given 调用方不理解来源差异，When 通过治理 interface 获取目录，Then 返回统一结构并保留只读/继承等能力事实。

## 9. 迁移与删除顺序

1. 先锁定两个 adapter 的共同规则、来源特有规则和 code 匹配规则的 contract test。
2. 旧 controller 只保留 `kind` 到新 interface 的兼容映射，所有写入单向进入治理 module。
3. 静态搜索确认 controller、任务和其他调用方不再直接写入两个 adapter 后，删除旧的直接写入路径。
4. 迁移失败时回滚兼容映射，不恢复第二条权威写入路径。

## 10. 依赖与风险

- 依赖现有字典与模板数据模型、版本字段、审计模型和访问能力矩阵。
- 不新增总部到门店的持续同步任务。
- 风险：来源无关 interface 可能隐藏必要的只读差异；通过结果中的能力事实和 contract test 保留差异。
