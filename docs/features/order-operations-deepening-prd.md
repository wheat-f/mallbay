| 项目 | 内容 |

| 关联代码 | `apps/api/src/orders/orders.service.ts`、`orders.controller.ts`、`orders.module.ts` |

## 2. 需求背景

`OrdersService` 当前同时承载订单查询、商业字段调整、付款、修订申请、支付账户、审计读取以及履约转发，1,345 行 implementation 通过一个宽 interface 暴露给两个 controller 和大量测试。调用者必须了解金额裁剪、权限、幂等、审计和事务细节。

本期目标是深化“订单运营”，不重做已由 `OrderLifecycle`、`PricingDecision` 和 `CashFactWriter` 拥有的事实。

## 3. 产品目标

- 订单运营读取与命令分别拥有小而深的 public seam。
- 订单列表、详情、导出、付款读取和审计读取共享稳定结果语义。
- 商业调整、修订申请、订单付款和支付账户操作集中事务、权限和审计 locality。
- 旧 `OrdersService` 不再作为 `OrdersModule` 的 public export。

## 4. 本期范围

### 包含

- 订单读取：列表、详情、导出、付款列表、订单审计、支付账户读取及审计。
- 订单命令：复制草稿、商业调整、修订申请创建/审核、订单付款、支付账户创建/修改/删除。
- 既有 controller 与页面调用者迁移。
- contract test、静态删除测试、全量回归。

### 不包含

- 新增或改造订单履约状态；履约继续由 `OrderLifecycle` authority 执行。
- 新增定价规则或回算价格/成本快照。
- 直接写 `PaymentRecord`；现金事实继续由 `CashFactWriter` 写入。
- 企业结算、退货、售后、库存和质保流程。

## 5. 核心对象与职责

| 对象 | 定义 | 本期职责 |
|---|---|---|
| 订单运营读取结果 | 面向订单列表、详情和导出的稳定业务投影 | 统一金额可见性、订单范围、履约摘要和生成时间 |
| 订单运营命令结果 | 一次商业、付款、修订或账户管理动作的业务结果 | 返回稳定结果、幂等重放结果和拒绝原因 |
| 订单履约结果 | 订单阶段、能力、阻塞原因和履约版本 | 由 `OrderLifecycle` 生成，订单运营只组合/转发 |
| 现金事实 | 实际收款及来源、反向关系 | 由 `CashFactWriter` 生成，订单运营只编排 |

## 6. 流程与业务规则

### 6.1 读取流程

1. 调用者提交访问主体、门店和查询条件。
2. 读取 seam 通过 `AccessContext` 判断门店/本人范围。
3. implementation 查询订单及必要的履约摘要、客户、车辆和金额。
4. 根据访问能力裁剪内部成本/利润字段，并返回稳定投影。
5. 详情需要履约解释时读取 `OrderLifecycle` 的权威结果，不自行推断阶段。

### 6.2 命令流程

1. 调用者提交明确的订单运营动作和输入。
2. seam 校验访问主体、对象存在性、状态和幂等条件。
3. 需要事务的动作在一个事务中完成业务事实、审计和关联事实编排。
4. 订单付款通过 `CashFactWriter` 写入现金事实；不得由订单运营直接创建 `PaymentRecord`。
5. 重放返回原结果；相同幂等键但请求摘要不同必须拒绝。

### 6.3 履约排除规则

取消、回退、最终交付和生命周期读取仍调用 `OrderLifecycle`。订单运营不得直接修改订单履约状态、履约版本或命令记录。

## 7. 权限与数据范围

| 角色/范围 | 读取 | 命令 |
|---|---|---|
| 销售本人 | 本人订单及允许的订单客户化字段 | 本人订单复制、允许的商业调整和修订申请 |
| 店长/管理者 | 授权门店订单及可见金额 | 门店订单运营、修订审核、支付账户管理 |
| 财务 | 授权门店订单、内部成本/付款信息 | 订单付款、支付账户管理 |
| 其他主体 | 由 `AccessContext` 决定 | 无能力时返回稳定拒绝结果 |

具体能力沿用现有 `orders`、`store`、`finance` capability/action/scope，不恢复 `PermissionPolicy` 或 `isAuditor` 判断。

## 8. 异常与边界

- 订单不存在、已被转移或超出范围：返回稳定 NotFound/Forbidden 语义，不泄露对象存在性。
- 商业调整遇到已付款、已有价格/成本快照或不允许状态：拒绝且不产生部分写入。
- 付款重复提交：同键同摘要返回原结果；同键不同摘要拒绝。
- 现金事实写入失败：整个订单付款事务回滚，不能只更新订单付款状态。
- 支付账户删除前仍被引用：沿用现有保护规则，拒绝删除并保留审计。
- 并发审核/修改：使用现有状态条件和唯一约束，失败返回可重试的业务错误。

## 9. 页面与调用者迁移

订单列表、详情、导出、付款和支付账户页面保持现有业务行为；只把调用入口迁移到新读取/命令 seam。页面不得自行拼装金额裁剪、履约阶段或付款状态。

## 10. 验收标准

- Given 用户仅有本人订单读取范围，When 查询门店订单列表，Then 只返回本人订单且不返回内部成本/利润字段。
- Given 订单详情需要履约阶段，When 读取详情，Then 阶段来自 `OrderLifecycle` 权威结果，页面不自行推断。
- Given 商业调整满足现有状态与权限条件，When 提交调整，Then 订单金额/订单项/审计在一个事务中完成。
- Given 付款命令首次提交，When `CashFactWriter` 成功，Then 订单付款结果与现金事实同时可见。
- Given 相同付款幂等键和相同请求摘要重复提交，When 执行命令，Then 返回原业务结果且不生成第二条现金事实。
- Given 相同幂等键但请求摘要不同，When 执行命令，Then 请求被拒绝且原事实不变。
- Given 生产源代码扫描旧入口，When 检查跨模块调用者与 module exports，Then 不存在对 `OrdersService` public export 的依赖。

## 11. 阶段门

1. 新读取/命令 seam contract test 覆盖投影、权限、事务、幂等和错误。
2. 两个 orders controller、web 订单调用者和测试迁移完成。
3. `OrdersModule` 不再 exports `OrdersService`，静态引用扫描和删除测试通过。
4. API typecheck、Nest build、全量 API tests 和订单/财务/履约代表页面验收通过。

## 12. 待确认事项

无业务阻塞项。支付账户的既有删除保护和商业调整的既有状态条件以当前代码行为与回归测试为准，不在本期扩大业务规则。
