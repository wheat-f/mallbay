# 权限模型改造 PRD 研发评审记录

## 1. 评审对象

- 文档：`docs/features/permission-model-redesign-prd.md`
- 评审日期：2026-07-31
- 评审范围：业务规则、权限语义、存量迁移、后端鉴权、前端联动、数据范围、缓存一致性、审计、测试与发布安全。
- 代码依据：当前后端仍由 `isAuditor`、`StoreMember.position` 和 `apps/api/src/common/policies/permission.policy.ts` 共同决定访问权限。

## 2. 第一轮问题清单

| 编号 | 等级 | 问题 | 影响 | 处理结论 |
|---|---|---|---|---|
| R1 | S0 | `permissionCode` 中的 scope、角色授权 scope、用户绑定 scope 的语义和组合算法未定义 | 不同研发人员可能实现出不同的放行结果，无法可靠测试越权 | 在 PRD 增加三层范围模型、范围包含关系和统一判定算法 |
| R2 | S0 | 权限版本没有明确的唯一生效版本、并发发布、回滚生成方式和旧草稿处理规则 | 可能出现两个生效版本、覆盖他人草稿或回滚后状态不一致 | 增加版本状态机、乐观锁、发布/回滚事务和幂等规则 |
| R3 | S0 | `OWN/STORE/GLOBAL` 没有逐资源的解析契约，未定义对象所有人、门店归属和查询过滤方式 | 列表接口容易只做按钮鉴权而发生横向越权 | 增加资源范围解析器、列表/详情/写操作统一规则及无解析器默认拒绝 |
| R4 | S1 | 存量迁移只有角色映射，没有迁移窗口、双读/双写、切换标志和失败恢复规则 | 切换时可能丢权或出现新旧权限同时放行 | 增加迁移阶段、兼容期、切换门槛和异常处理；兼容字段仅用于迁移与回滚 |
| R5 | S1 | `isAuditor` 到总部角色的映射过于模糊，未规定是否拆分总部管理员和审计角色 | 总部账号迁移后权限可能扩大或缩小 | 明确首期按现有行为映射为总部管理员，并把审计只读拆分列为后续角色，不改变首期权限 |
| R6 | S1 | “绑定即时生效”与 30～60 秒 TTL 建议存在冲突 | 解绑后短时间仍可能访问受保护资源 | 改为提交事务成功后必须失效；缓存仅作加速，使用版本标记/同步失效，无法确认新版本时默认拒绝 |
| R7 | S1 | 前后端统一结果只描述为“统一接口”，缺少响应结构和旧接口兼容策略 | 前端无法稳定控制菜单、按钮、数据范围，调用方迁移无依据 | 增加统一响应结构、权限版本、角色绑定范围和旧能力接口过渡规则 |
| R8 | S1 | 影响分析、发布确认和回滚的输入输出不够明确 | 发布前无法判断影响是否已被确认，回滚也无法保证可执行 | 增加分析快照、确认版本号、失效原因、回滚兼容条件和审计要求 |
| R9 | S1 | 角色停用、用户停用、门店关系不存在、多门店上下文等安全边界没有统一定义 | 容易因只检查角色而绕过用户或组织边界 | 增加安全边界优先级、请求门店上下文及跨门店拒绝规则 |
| R10 | S1 | 现有业务接口数量较多，PRD 没有给出权限目录映射和统一 Guard/Service 接入要求 | “发布后控制后端”无法验收，容易只改部分模块 | 增加接口盘点清单作为研发交付物，并规定受保护接口必须经过统一鉴权服务 |
| R11 | S2 | 审计查询权限、留存、分页和敏感字段处理未定义 | 发生权限事故后难以定位或审计数据泄露 | 复用现有审计事件模型，补充分页、留存配置、脱敏和查询权限 |
| R12 | S2 | 指标只有名称没有口径和基线 | 上线后无法判断改造是否有效 | 补充计算口径，目标值保留为上线前基线确认项，不阻塞研发设计 |

## 3. 第一轮结论

结论：**暂不通过研发评审**。

原因：R1、R2、R3 属于 S0，直接影响后端数据模型、鉴权算法和测试边界；R4～R10 属于 S1，影响迁移上线和真实权限闭环。必须先修订 PRD，再进行第二轮评审。

## 4. 修订要求

修订后的 PRD 必须至少包含：

1. 三层权限范围的判定算法和资源解析契约。
2. 权限版本状态机、并发控制、发布与回滚事务。
3. 迁移阶段、兼容期、切换门槛和 `isAuditor` 的首期映射。
4. 即时生效下的缓存一致性方案。
5. 统一权限响应结构和旧接口过渡策略。
6. 统一后端鉴权入口及接口盘点交付物。
7. 影响分析确认、最后管理员保护和跨组织安全边界。

## 5. 第二轮复审结论

已核对修订后的 PRD：三层范围判定、统一鉴权入口、版本并发与回滚、迁移切换、即时生效、统一响应和验收交付物均已明确；顶部状态和绑定生效时点的文档一致性问题已修正。未发现新的 S0/S1 阻塞项。

结论：**通过研发评审，可进入研发。**
