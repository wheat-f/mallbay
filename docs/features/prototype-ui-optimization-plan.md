# 原型对齐 UI 优化方案

## 文档信息

- 文档状态：实施中
- 原型来源：`/Users/es/Downloads/stitch_mallbay`
- 需求依据：`docs/features/paint-protection-film-system-plan.md` 与 Phase 1-6 功能说明
- 适用范围：Web 管理端页面、师傅端小程序页面的信息架构与首屏可用性

## 当前判断

最新原型已覆盖订单、客户、施工、库存采购、质保、售后、财务、发票、返利、报表、系统设置和小程序离线等核心模块。当前代码也已有对应路由和 API 调用，但部分页面仍偏“表单 + 表格”，与原型中的运营工作台式结构存在差距。

本轮不重写业务逻辑，不新增后端状态机，只做低风险 UI 与信息架构优化。

## 优化原则

- MUST 保持现有 API、权限和状态流转不变。
- MUST 优先优化已有数据支撑的页面，不引入假交互替代真实业务。
- MUST 保持页面可回滚，每个页面的优化边界清晰。
- SHOULD 使用原型中的“指标区 + 流程区 + 操作区 + 明细区”结构。
- SHOULD 把风险、待处理事项和下一步操作放在首屏。

## 第一批实施范围

### 1. 订单管理

对齐原型：`_47 销售订单列表`

实施内容：

- 增加订单指标区：订单数、总金额、待收金额、异常订单数。
- 增加快捷状态入口：全部、待派工、施工中、已完工、已取消。
- 保留当前筛选和分页能力。

### 2. 施工容量

对齐原型：`_7/_17/_35/_54 施工产能设置`

实施内容：

- 增加产能概览：已维护日期、今日总容量、今日已预约、超量风险。
- 保留从订单页跳转返回订单的能力。
- 保留已有容量维护表单和列表。

### 3. 库存采购

对齐原型：`_3 采购需求与审批`、`_8/_40 采购与入库管理`、`_48 库存匹配与出库`、`_49 库存调整与单位转换`

实施内容：

- 增加库存采购流程入口：待匹配、供应商、批次、采购、流水、拆分、其他出入库。
- 增加风险提示：待匹配订单、待处理采购需求、采购到货提醒。
- 保留现有全部标签页和 API 行为。

### 4. 质保管理

对齐原型：`_25 质保查询与管理`、`_10/_68 质保登记台`

实施内容：

- 分离“生成质保”和“质保查询”区域。
- 增加质保概览与电子质保卡预览入口。
- 保留按质保编号查询和列表能力。

### 5. 提成管理

对齐原型：`_61 施工质检 & 提成审核`、`_67 佣金规则配置`

实施内容：

- 分离规则配置、销售提成生成、师傅提成生成三个操作区。
- 增加说明性状态区，强调规则与生成日志的边界。

## 暂缓范围

以下内容需要更多 API 或权限闭环，不在第一批做界面承诺：

- 独立采购订单详情页。
- 独立质保详情页。
- 独立库存流水路由。
- 小程序售后任务完整流。
- 原型中的复杂图表和 AI 洞察。

## 第二批实施范围

第二批优先补齐原型新增的“详情页闭环”，避免列表页只能查看摘要、无法承接到货验收和质保追溯。

### 1. 采购订单详情与到货验收

对齐原型：`_73 采购订单详情与到货验收`

实施内容：

- 新增 `/inventory/purchase-orders/[id]` 页面。
- 从现有采购订单列表数据中定位采购单，展示基本信息、采购清单、到货提醒和流转日志。
- 在采购明细下保留单批次入库和批量扫码入库入口。
- 在 `/inventory` 采购订单表中增加“详情”入口。

### 2. 质保详情

对齐原型：`_74 质保详情`

实施内容：

- 新增 `/warranties/[id]` 页面。
- 使用 `warrantiesApi.detail(id)` 展示质保核心信息、关联订单和到期提醒。
- 增加原材料溯源、施工影像存证、售后追溯的业务说明区，当前通过关联订单承接后续追溯，不伪造不存在的数据。
- 在 `/warranties` 列表中增加“详情”入口。

## 第三批实施范围

第三批来自补充原型 `_75`、`_76`。这两个原型涉及提成结算批次和订单创建后的流转确认；当前后端已有提成生成、订单审计、库存匹配、施工派工能力，但还没有独立“提成结算批次”模型，因此本批只做真实数据可支撑的界面收敛。

### 1. 提成结算与生成记录

对齐原型：`_75 提成结算与生成记录`

实施内容：

- 在 `/commissions` 增加可结算订单、施工记录、提成规则概览。
- 增加“结算日志明细”区域，用现有规则、已完工订单和施工记录展示可结算来源。
- 明确当前版本不伪造已结算流水，真正的结算批次、导出和明细抽屉进入后续财务批次。

### 2. 销售下单后确认流转

对齐原型：`_76 销售下单 - 确认流转`

实施内容：

- 在 `/orders/[id]` 的 `PENDING_DISPATCH` 状态下展示“确认提交派工与库房匹配”区。
- 提醒销售核对客户、车辆、产品和施工要求。
- 提供进入库存匹配和施工派工的真实页面入口。
- 不允许订单详情页直接改写施工状态，库存和派工仍由对应模块控制。

## 验证方式

- `corepack pnpm --filter @mallbay/web typecheck`
- 相关页面测试：订单、施工容量、库存、质保、提成 display/page 测试。
- 浏览器打开代表页面，确认首屏结构和原型方向一致。
