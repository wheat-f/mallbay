## 2. 背景与问题

当前系统设置将角色权限、基础字典、门店配置、账号设置、通知/OSS 等内容堆叠在同一页面，造成以下问题：

1. 店长、财务、总部管理员看到大量与自身职责无关的配置，无法快速定位工作。
2. 页面存在静态指标、不可用按钮或保存后不生效的反馈，用户无法判断配置是否真正写入服务端。
3. 权限边界主要依赖前端隐藏，直接访问地址或调用接口时缺少统一的后端校验。
4. 字典只有大类启用/禁用，无法定位到具体小类；系统内置项、总部模板和门店自定义项的关系不清晰。
5. 配置缺少草稿、校验、发布、版本和审计闭环，容易影响正在使用的业务。

本 PRD 以“职责工作台”为核心，将系统设置拆分为总部治理、门店运营、财务结算和个人账号四类职责空间，并建立统一的版本化配置与审计机制。

## 3. 产品目标

### 3.1 目标

- 用户登录后只看到与其角色相关的设置能力。
- 总部管理员维护全局权限、字典模板和安全策略。
- 店长维护本门店业务配置，不可修改总部权限、全局字典和财务成本规则。
- 财务维护岗位小时成本、成本/结算规则和收款账户，不可配置派工、门店业务开关。
- 所有重要配置均支持草稿、服务端校验、发布生效、版本追踪和审计；本期不设置审批节点。
- 禁用、保存、发布等操作均以服务端结果为准，并在页面上明确反馈。

### 3.2 非目标

- 本期不重做销售订单、采购、库存、施工、发票等业务流程。
- 本期不开放任意自定义角色创建；仅维护既有角色及其能力范围。
- 本期不实现跨门店财务合并核算。
- 本期不改变历史订单已冻结的配置快照。

## 4. 角色与权限模型

### 4.1 角色定义

| 角色 | 主要职责 | 可维护范围 | 明确禁止 |
|---|---|---|---|
| 总部管理员 | 全局治理 | 全局权限、字典模板、安全策略、全局审计 | 无（受系统安全规则约束） |
| 店长 | 门店日常运营 | 当前门店资料、业务开关、通知、预约/容量默认值、本地业务审计 | 角色权限、总部字典模板、财务成本与结算配置 |
| 财务 | 成本与结算 | 当前门店的岗位小时成本、成本/结算规则、收款账户、财务审计 | 其他门店及总部配置、派工、门店运营开关、全局权限 |
| 销售/客服/施工主管/师傅 | 业务使用 | 按现有业务权限只读或使用相关配置 | 系统设置写入 |

### 4.2 权限维度

权限由“角色 × 能力 × 操作 × 数据范围”组成：

- 能力：例如 `settings.permissions`、`settings.dictionary`、`store.profile`、`finance.labor_cost`。
- 操作：`view`、`create`、`edit`、`enable`、`disable`、`validate`、`publish`、`audit`。
- 数据范围：`global`、`store`、`own`、`read_only`。
- 后端必须对每个读写接口进行同样校验，前端隐藏按钮不构成授权。

### 4.3 权限判定规则

1. 用户没有 `view` 权限时，不返回模块数据，并返回 403。
2. 用户有 `view` 但没有写权限时，页面以只读方式展示，不显示保存、发布、启停按钮。
3. 店长访问其他门店数据时，返回 403；店长只可访问当前门店。
4. 财务只能读取或维护当前门店财务范围内的数据；不得通过前端参数切换到总部或其他门店配置。
5. 总部管理员发布权限变更后，新会话和新请求立即使用新权限；已打开页面必须在保存时再次校验。

### 5.1 设置首页

首页根据登录角色加载“我的职责”卡片，不展示无权模块。每张卡片包含：模块名称、当前状态、最后更新时间、待处理事项、进入按钮。

页面必须展示：

- 配置状态：正常、待发布、校验失败、权限不足。
- 数据来源：总部模板、门店配置、财务版本。
- 多角色用户按能力并集授权，数据范围取最小安全范围；角色和门店变更对下一次请求生效。
- 总部管理员默认可查看各门店配置但不可直接修改门店配置；本期不开放总部代维护，后续如开放必须单独授权并记录审计。
- 最后更新时间、操作人和版本号。
- 统一的“查看全部设置”入口，但无权模块进入后应返回 403 页面，而不是空白。

## 6. 核心业务对象

### 6.1 配置能力（Settings Capability）

| 字段 | 类型 | 说明 |
|---|---|---|
| code | string | 能力编码，例如 `settings.dictionary` |
| name | string | 中文显示名称 |
| domain | enum | `HQ`、`STORE`、`FINANCE` |
| allowedRoles | role[] | 可访问角色 |
| actions | object | 操作级权限定义 |
| status | enum | 启用/停用 |

### 6.2 配置版本

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 版本 ID |
| domain | enum | 所属职责域 |
| scopeId | string | global 或门店 ID |
| version | string | 例如 v1、v2 |
| status | enum | 草稿、校验中、校验失败、已发布、已过期、已撤回 |
| effectiveAt | datetime | 生效时间 |
| payload | JSON | 配置快照；结构由各模块定义 |
| createdBy/updatedBy | string | 创建、更新人 |
| publishedBy | string | 发布人 |

### 6.3 基础字典与字典项

字典采用“系统固定 > 总部模板 > 门店自定义”的继承顺序。总部禁用项对所有门店生效，门店不可重新启用；门店只能新增本店自定义项，不能覆盖总部同编码。字典项必须包含：

- `dictionaryCode`、`itemCode`、`label`、`sortOrder`。
- `source`：系统固定、总部模板、门店自定义。
- `enabled`：启用/禁用。
- `referencedCount`：被产品、订单、规则等业务数据引用次数。
- `deletePolicy`：系统固定和总部模板不可删除；被引用项只允许禁用；未引用的本店自定义项可删除。历史单据保存字典编码、名称、来源和当时启用状态快照。

### 6.4 审计记录

每次保存、校验、发布、启用、禁用、校验失败、撤回都写入审计记录：

- 操作人、角色、门店、时间、IP/设备（如合规允许）。
- 能力、对象 ID、操作类型。
- 变更前摘要、变更后摘要、原因、结果。
- 失败时记录错误码和服务端校验信息。

## 7. 关键流程

```mermaid
flowchart LR
  A[进入设置工作台] --> B[按角色加载能力]
  B --> C[进入职责模块]
  C --> D[编辑配置草稿]
  D --> E[保存草稿]
  E --> F{服务端校验}
  F -->|失败| D
  F -->|通过| G[具备发布权限即可发布]
  G --> H[发布生效]
  H --> I[生成版本与审计记录]
```

### 7.1 进入与授权

1. 用户打开 `/settings`。
2. 服务端根据用户角色、门店和能力策略返回可见模块。
3. 前端只渲染有 `view` 权限的卡片。
4. 用户通过直链访问无权模块时，服务端返回 403，页面展示“当前角色无权访问”和返回首页按钮。

### 7.2 草稿、校验与发布

1. 用户编辑配置并点击“保存草稿”。
2. 前端提交完整配置版本和客户端版本号。
3. 服务端校验必填项、枚举值、冲突、引用关系和权限。
4. 保存成功后，前端必须重新读取服务端数据，显示版本号、更新时间和操作人。
5. 本期不设置审批；具备 `publish` 权限的角色在校验通过后可直接发布。
6. 发布时再次校验版本是否过期，避免并发覆盖；成功后生成审计记录。
7. 发布后的版本不可直接修改，只能创建新草稿；新版本生效前不影响历史快照。

### 7.3 字典项启用/禁用

1. 在字典树中选择大类后展示小类项。
2. 每个小类有独立的启用/禁用开关和引用状态。
3. 禁用前提示影响范围；已被引用项不得删除。
4. 保存后服务端返回最新状态，页面重新拉取并显示“已生效”。
5. 若保存失败，保留用户输入并展示具体字段错误，禁止假显示成功。

## 8. 功能需求

### 8.1 设置首页（P0）

- 根据角色展示职责卡片。
- 显示待发布、校验失败数量。
- 支持最近访问、最近变更和审计入口。
- 不展示未实装按钮；未完成能力显示“规划中”并不可点击。

### 8.2 总部治理

#### 8.2.1 角色与权限

- 以角色为行、业务能力为列展示权限矩阵。
- 支持查看、编辑、发布三个层次；操作级权限可展开查看。
- 修改后先保存草稿，再校验冲突（例如同一角色缺少必要的基础查看权限）。
- 发布前展示影响角色、模块和门店数量。
- 发布成功后记录完整差异。

#### 8.2.2 基础字典模板

- 以“大类 → 小类”树形结构维护。
- 支持新增自定义项、编辑显示名称、排序、启用/禁用。
- 系统固定编码不可修改；自定义编码不可与现有编码重复，冲突时服务端提示“编码已存在，请更换编码”。
- 显示被引用数量和引用模块；被引用项仅可禁用。
- 展示继承来源、总部禁用状态和门店可操作范围；总部禁用项不可被门店重新启用。支持导出字典配置；首期支持新增型 Excel 导入，不支持覆盖式导入，导入失败整批回滚。

#### 8.2.3 安全策略

- 登录会话、密码策略、二次验证、操作超时等安全项分组展示。首期会话闲置 30 分钟失效、密码至少 8 位且含字母和数字、连续失败 5 次锁定 15 分钟；MFA、IP 白名单、设备管理和异常风险识别列入二期。
- 修改敏感安全策略需要二次确认并写审计。
- 生效时间和影响范围必须明确；不允许保存后静默生效。

#### 8.2.4 全局审计

- 按时间、操作人、角色、模块、对象、结果筛选。
- 支持查看变更前后差异。
- 支持 Excel/CSV 导出，单次最多 10,000 条；按当前角色范围和脱敏规则导出，导出行为写入审计。

### 8.3 门店运营

- 店长仅维护当前门店业务配置；总部禁用的字典项和开关不可在门店重新启用。
- 保存后重新读取服务端版本，默认发布立即生效；成本/结算类版本可设置未来生效时间，且同一门店生效时间不得重叠。

### 8.3.0 个人与账号设置

- 用户维护个人资料、密码和已登录设备；角色及门店归属由人员管理维护。
- 店长和财务不可自行提升角色或切换门店数据范围。

#### 8.3.1 门店资料

- 店长可维护门店名称、地址、联系电话、营业时间等门店字段。
- 字段是否可为空沿用现有门店模型；新增字段需产品评审。
- 只能编辑当前门店，保存后展示服务端返回值。

#### 8.3.2 业务开关

- 店长可维护本门店业务开关，例如预约、库存预警、施工流程照片、短信提醒。
- 每个开关显示当前值、说明、影响模块和最近修改人。
- 关闭高风险开关时必须填写原因并二次确认。

#### 8.3.3 通知与 OSS

- 店长可维护本门店通知接收人和业务提醒开关。
- OSS 配置涉及密钥时只显示脱敏值，不回显完整密钥。
- 测试连接必须由服务端执行，失败时返回可读错误。

#### 8.3.4 预约与容量默认值

- 店长配置到店、外出、玻璃膜、复检等施工容量默认值。
- 保存前校验不能为负数，容量冲突时显示具体日期和业务类型。

### 8.4 财务结算

#### 8.4.1 岗位小时成本

- 财务仅维护当前门店岗位、小时成本、有效期和版本，不能读取或修改其他门店数据。
- 已发布版本不可修改；通过新版本调整。未填写 effectiveAt 时按当前门店时区立即生效。
- 版本生效后，新订单使用新版本，历史订单保留原快照；未填写 effectiveAt 时按当前门店时区立即生效。

#### 8.4.2 成本与结算规则

- 财务维护标准成本组成、结算口径、成本来源优先级。
- `finance.settlement` 使用版本化策略配置，必须明确实际入库价优先、标准材料成本兜底、缺失成本处理、提成来源、结算冻结节点和成本调整审批策略。
- 当前已发布策略为：实际入库价优先、标准成本兜底、实际成本缺失时禁止确认、提成取财务最终值、`SETTLED` 后冻结、成本调整仅财务审批。
- 已完成成本结算的订单成本永久冻结；未结算订单允许在规则允许范围内刷新，并标注实际、标准或待补齐来源。

#### 8.4.3 收款账户

- 财务维护账户名称、账户类型、启用状态和默认账户。
- 停用默认账户前必须先指定替代默认账户。
- 已产生流水的账户不允许删除，只允许停用。

#### 8.4.4 财务审计

- 财务只能查看当前门店财务域审计；不得通过 `domain` 参数读取门店业务审计。店长查看当前门店业务审计，总部审计员查看全局审计。
- 对金额、成本来源、收款账户的改动显示差异和原因。
- 审计记录追加写入不可删除；普通审计保留不少于 3 年，财务审计暂按 5 年保留。
- 金额、密钥等敏感字段按角色脱敏；导出密钥、密码和令牌时永不输出明文。
- 金额、密钥等敏感字段按角色脱敏；总部管理员查看全局，店长查看本店业务审计，财务查看本店财务审计。

## 9. 页面与交互规范

1. 页面标题使用中文职责名称，不使用仅靠英文编码理解的标签。
2. 每个分组标题后提供问号图标，悬停显示分组说明；字段级说明采用同样方式。
3. 保存按钮显示保存中、成功、失败三种状态；成功必须以服务端响应为准。
4. 保存失败时不清空表单，不显示成功绿条；错误定位到具体字段或分组。
5. 页面离开前若有未保存变更，弹窗提示“保存草稿/放弃/取消”。
6. 危险操作（删除、禁用、撤回、修改发布权限）必须二次确认并要求原因；本期发布无需审批，但必须记录发布审计。
7. 移动端和 1280px 以上桌面端均需保证操作按钮可见；表格支持横向滚动但不隐藏关键状态。

## 10. 接口与技术要求

以下为建议接口，具体路径、认证方式和分页结构需技术评审后确认：

| 接口 | 用途 |
|---|---|
| `GET /settings/capabilities` | 获取当前用户可见能力 |
| `GET /settings/summary` | 获取首页卡片状态和待办 |
| `GET/PATCH /settings/config-versions` | 读取/保存配置版本草稿 |
| `POST /settings/config-versions/:id/validate` | 服务端校验配置版本 |
| `POST /settings/config-versions/:id/publish` | 发布配置版本 |
| `GET /settings/dictionaries` | 获取字典树及引用信息 |
| `POST/PATCH /settings/dictionaries/{code}/items` | 新增/编辑字典项 |
| `POST /settings/dictionaries/{code}/items/{item}/status` | 启用/禁用字典项 |
| `GET/PATCH /stores/{storeId}/settings` | 门店资料与业务配置 |
| `GET/PATCH /settings/config-versions?capabilityCode=finance.*` | 财务配置草稿与版本 |
| `GET /settings/audit` | 查询审计记录（支持 domain/action/date/page/pageSize） |

技术要求：

- 所有写接口必须使用服务端权限校验和乐观锁/版本号校验。
- 列表接口统一使用 page/pageSize，默认 20、最大 100；审计导出最多 10,000 条。
- 配置读取返回 version、updatedAt、updatedBy 和 etag；发布成功后立即清理当前门店和用户缓存。
- 字典和门店配置缓存最长 5 分钟，发布/启停后主动失效；暂不引入消息队列。
- 写操作必须携带 requestId；同一 requestId 重试返回原结果，不重复创建配置或审计。
- 发布接口必须校验 effectiveAt、同门店版本时间范围和继承禁用规则。
- 返回统一错误结构：错误码、中文消息、字段路径、可重试标记。
- 写入成功后返回最新版本和更新时间，前端不得使用本地乐观值替代。
- 审计写入与业务配置写入必须保证一致性；失败时配置不得处于“已生效但无审计”状态。

## 11. 异常与边界

| 场景 | 处理 |
|---|---|
| 无权限访问直链 | 返回 403 页面，提供返回设置首页按钮 |
| 会话过期 | 保存前提示重新登录，禁止丢失草稿 |
| 并发编辑同一版本 | 拒绝覆盖，提示重新加载并比较差异 |
| 字典项已被引用 | 禁止删除，只允许禁用并展示引用模块 |
| 保存网络超时 | 标记为“未确认”，允许重试，不显示成功 |
| 草稿超过 30 天 | 到期前 7 天、1 天提醒；到期后标记已过期，只能复制为新草稿 |
| 审计导出超过 10,000 条 | 拒绝导出并提示缩小筛选范围 |
| 重复导入字典编码 | 逐行提示冲突，整批回滚 |
| 发布校验失败 | 保留草稿，展示字段/规则错误 |
| 服务端返回旧数据 | 自动重新读取；若版本未变化则提示刷新 |
| 重复提交同一写操作 | 通过 requestId 幂等处理，只生成一份配置和一条审计 |
| 生效时间重叠 | 服务端拒绝发布，提示已有生效版本的时间范围 |
| 总部已禁用字典项 | 门店显示禁用原因且不可重新启用 |
| 自定义编码冲突 | 拒绝保存并提示“编码已存在，请更换编码” |

## 12. 数据迁移与兼容

1. 迁移前备份原配置和数据库，生成校验点；将现有设置页面能力拆分为总部、门店、财务三个域，原配置数据按归属迁移。
2. 历史权限、字典、门店配置和财务版本生成迁移审计记录，操作人标记为“系统迁移”。
3. 迁移期间保留旧路由重定向到新职责工作台，旧路由只读，避免收藏链接失效。
4. 历史订单继续使用已保存的配置快照，不因新页面发布而重算。
5. 现有成本核算逻辑（岗位费率、材料成本、施工结算、提成快照、成本调整）保留不变；迁移脚本为每个门店生成 `finance.settlement` v1 策略版本，作为后续策略读取入口。
6. `Permissions` 与 `FinanceSettlement` 人工确认项必须由总部审计员以原因闭环，并写入迁移审计。
5. 对无法识别归属的旧配置进入“待人工确认”清单，不自动覆盖。迁移采用功能开关灰度；回滚时恢复旧配置读取路径，但保留新系统产生的审计记录。

## 14. 验收标准（Given / When / Then）

### 14.1 职责可见性

- Given 用户是店长，When 打开系统设置，Then 只显示门店运营工作台和允许查看的公共只读项。
- Given 用户是财务，When 打开系统设置，Then 只显示财务结算工作台和允许查看的公共只读项。
- Given 用户是总部管理员，When 打开系统设置，Then 可见总部治理、门店和财务配置入口。

### 14.2 越权防护

- Given 店长直接访问权限矩阵接口，When 请求发送，Then 服务端返回 403，前端展示无权页面。
- Given 财务尝试修改业务开关，When 提交保存，Then 服务端拒绝并记录失败审计。

### 14.3 字典小类

- Given 一个字典包含多个小类，When 仅禁用其中一项，Then 其他小类状态不变，服务端返回该项最新状态。
- Given 小类被订单或产品引用，When 尝试删除，Then 操作被阻止并显示引用数量；允许禁用。
- Given 小类来自总部且已禁用，When 门店尝试启用，Then 服务端拒绝并显示“总部已禁用”。
- Given 门店新增项使用已存在编码，When 保存，Then 服务端拒绝并提示“编码已存在，请更换编码”。

### 14.4 保存与发布

- Given 用户编辑配置，When 服务端保存成功，Then 页面重新读取并显示最新版本、时间、操作人。
- Given 服务端校验失败，When 用户点击保存，Then 表单保留输入，错误定位到字段，不能显示保存成功。
- Given 已发布版本，When 用户再次编辑，Then 系统创建新草稿，旧版本不可被直接改写。
- Given 用户具备发布权限且校验通过，When 点击发布，Then 无需审批即可发布并记录发布人、版本和审计。
- Given 同一门店存在重叠 effectiveAt，When 发布，Then 服务端拒绝并提示冲突版本。

### 14.5 历史数据

- Given 历史订单已使用旧配置，When 新版本发布，Then 历史订单金额、成本和审计快照不变。
- Given 新订单创建在新版本生效后，When 读取配置，Then 使用新版本。

### 14.6 审计与导出

- Given 财务用户导出审计，When 条件命中其他门店，Then 服务端按当前门店范围过滤。
- Given 导出包含敏感字段，When 生成 Excel/CSV，Then 字段按角色脱敏且密钥、密码、令牌不输出。
- Given 导出数量超过 10,000 条，When 提交导出，Then 服务端拒绝并提示缩小范围。

### 14.7 草稿生命周期

- Given 草稿保存已满 23 天，When 到达提醒任务，Then 创建人收到到期前 7 天提醒。
- Given 草稿已满 30 天，When 自动任务执行，Then 草稿标记为已过期，只能复制为新草稿且产生审计。

### 14.8 字典导入与安全

- Given Excel 导入存在重复编码，When 服务端校验，Then 逐行返回冲突并整批回滚。
- Given 用户连续登录失败 5 次，When 第 5 次失败发生，Then 账号锁定 15 分钟并写入审计。
