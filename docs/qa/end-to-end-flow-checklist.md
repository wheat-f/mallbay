## 2. 场景一：零定金、有库存订单闭环

- [ ] 创建订单时定金为 0，订单创建成功。
- [ ] 订单可以继续库存匹配，不因零定金阻断。
- [ ] 人工选择库存批次和数量后锁库。
- [ ] 出库后才能进入施工派工。
- [ ] 施工人员领取物料后才能开工。
- [ ] 施工完成后订单进入待质检，不直接标记订单完成。
- [ ] 质检通过后允许生成质保卡。
- [ ] 尾款未清时质保卡状态为 `PENDING_ACTIVATION`，起止日期为空。
- [ ] 尾款结清后系统自动最终交付，订单变为 `COMPLETED`。
- [ ] 最终交付时质保卡变为 `ACTIVE`，起始日为最终交付日。
- [ ] 最终交付时尚未生成质保卡，系统自动创建并同时生效。
- [ ] 尾款待办在工作台可见，结清后自动关闭。

- 施工记录号：
- 质保号：
- 最终交付审计事件：

## 3. 场景二：缺货采购恢复匹配

- [ ] 库存不足时生成采购需求。
- [ ] 采购订单完成审批后才能到货入库。
- [ ] 采购到货由采购或店长人工确认。
- [ ] 到货只增加可用库存，不自动锁定订单批次。
- [ ] 到货后订单重新进入待匹配队列。
- [ ] 人工选择批次和数量后锁库，再执行出库。

记录：

- 订单号：
- 采购需求号：
- 采购订单号：
- 到货批次号：
- 人工确认人：

## 4. 场景三：质检不通过返工与复检

- [ ] 质检不通过时必须填写返工说明和责任类型。
- [ ] 订单进入独立返工状态，不进入最终交付。
- [ ] 返工记录复用施工记录快照和审计事件。
- [ ] 返工历史可在订单详情中查看。
- [ ] 返工完成后重新质检。
- [ ] 复检通过后才能生成质保或触发最终交付。
- [ ] 重复提交同一操作不会产生重复返工或审计记录。

记录：

- 订单号：
- 施工记录号：
- 返工审计事件：
- 复检结果：

## 5. 场景四：历史数据核验

- [ ] 历史 `COMPLETED`/`WARRANTIED` 订单缺少质检结果时进入待核验列表。
- [ ] 系统不自动回写历史质检结果。
- [ ] 仅店长/管理员可确认历史记录。
- [ ] 已有质检结果的历史订单不能重复确认。
- [ ] 历史核验写入审计事件。

## 6. 幂等与权限

- [ ] 重复收款请求通过幂等键返回首次结果，不重复记账。
- [ ] 重复生成质保不产生重复质保卡。
- [ ] 重复最终交付不重复更新订单、质保、待办或审计。
- [ ] 销售只能处理本人订单范围内的业务数据。
- [ ] 财务可处理收款和尾款待办，但不能修改客户主数据。
- [ ] 客服、采购、施工等角色遵循门店和职责边界。
