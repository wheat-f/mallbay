# 系统设置重构设计方案

**日期：** 2026-07-28  
**状态：** 待评审设计稿  
**范围：** `/settings` 系统设置及其关联配置入口

## 1. 设计目标

当前系统设置页面将权限矩阵、字典、门店配置、账号、通知服务和审计信息堆叠在一个长页面，导致：

- 使用人员无法快速判断“我应该维护什么”；
- 页面存在静态矩阵、模拟开关和未接通按钮，容易造成误判；
- 总部、店长、财务的职责边界没有在页面上体现；
- 配置保存、发布、生效和审计状态不清晰；
- 字典大类、小类、逐项启停与业务引用关系缺少统一入口。

重构后，系统设置采用“按职责分区、按任务进入、按版本生效”的结构：

1. 总部管理员维护全局权限、字典模板和安全策略；
2. 店长维护当前门店的业务配置；
3. 财务仅维护岗位小时成本、成本单价和结算策略；
4. 其他角色只看到与自己相关的只读说明，不进入维护页面；
5. 所有可修改配置均显示真实状态、最近保存人、待发布变更和审计入口。

## 2. 推荐方案与备选方案

### 方案 A：职责工作台（推荐）

系统设置首页只显示当前角色可执行的任务卡片，点击后进入独立页面：

- 总部治理：权限与岗位、字典模板、安全与审计；
- 门店经营：门店资料、业务开关、通知偏好、容量默认值；
- 财务结算：岗位小时成本、结算规则、收款账户可见范围。

优点：职责清晰、页面短、最容易隐藏未授权能力；缺点：页面和路由数量增加。

### 方案 B：同页分区

保留 `/settings` 单页，但按角色显示三个大分区，子项使用折叠面板。

优点：改造成本较低；缺点：页面仍会变长，配置项多时仍容易迷路。

### 方案 C：配置中心 + 独立模块页

首页只做导航，所有配置完全拆成独立模块，并增加全局搜索。

优点：长期扩展性最好；缺点：一期需要同步完成更多路由、权限和导航改造。

**建议采用方案 A，一期保留方案 C 的路由结构，后续逐步增加全局搜索。**

## 3. 信息架构

```text
系统设置
├── 设置首页（按角色展示待办与状态）
├── 总部治理（总部管理员）
│   ├── 岗位与权限
│   ├── 基础字典模板
│   ├── 安全策略
│   └── 全局审计
├── 门店经营配置（店长）
│   ├── 门店资料
│   ├── 业务开关
│   ├── 通知偏好
│   └── 容量与预约默认值
└── 财务结算配置（财务）
    ├── 岗位小时成本
    ├── 成本与结算口径
    ├── 收款账户
    └── 财务审计
```

## 4. 首页设计

### 4.1 顶部区域

- 页面标题：系统设置；
- 当前门店/当前角色标签；
- 配置环境标签：总部模板、门店草稿、已发布；
- 全局搜索框：搜索设置项、字典、岗位或审计记录；
- 右侧显示“待处理变更”数量和“最近操作”。

### 4.2 角色工作台卡片

只显示当前角色有权限进入的卡片。每张卡片必须包含：

- 配置名称；
- 用途说明；
- 当前状态：正常、草稿、待发布、异常；
- 最近更新时间和操作人；
- 进入配置按钮；
- 未授权时不显示按钮，不使用点击后再提示“无权限”。

### 4.3 状态摘要

首页只保留真实可计算的数据：

| 指标 | 来源 |
|---|---|
| 待发布变更 | 服务端配置版本 |
| 字典异常 | 字典项冲突、空必选项、引用停用项 |
| 权限待确认 | 权限草稿与已发布版本差异 |
| 成本版本 | 当前生效岗位小时成本版本 |
| 审计待处理 | 未完成审批或失败记录 |

删除当前页面中“业务模块 13”“权限等级 4”等静态 KPI，除非这些数据由服务端实时返回。

## 5. 总部治理模块

### 5.1 岗位与权限

页面分为三个步骤：

1. 岗位列表：系统岗位、门店岗位、启用状态、成员数、适用范围；
2. 权限编辑：按模块和动作展示权限，而不是只有“完全控制/部分权限”宏观标签；
3. 发布确认：显示影响岗位、受影响门店、风险提示和审计原因。

权限动作至少拆为：查看、创建、编辑、审批、导出、结算、配置。数据范围单独配置：本门店、本人、本组、全门店、总部。

总部管理员可以维护模板，但门店店长不能改变总部模板的核心权限；店长可在允许范围内绑定本店成员和数据范围。

### 5.2 基础字典模板

沿用已设计的分层字典能力，但页面改为树形维护：

- 大类/小类树；
- 每个字典项独立启用/禁用；
- 系统项、总部模板项、门店自定义项清晰区分；
- 编码、引用次数、最后修改人、版本号可见；
- 已引用项只能停用不能删除；
- 保存成功后强制回读服务端，禁止只更新前端状态。

总部管理员维护“模板项”和策略开关，店长在门店设置中维护允许的门店项。

### 5.3 安全策略

首期配置：

- 登录会话有效期；
- 密码策略；
- 多端登录限制；
- 敏感操作二次确认；
- 导出和批量操作审计；
- 个人数据、成本和工资字段的可见范围。

所有策略显示“当前值、草稿值、生效时间、发布人”，不再使用不可点击的说明卡片代替功能。

### 5.4 全局审计

支持按时间、操作人、门店、配置类型、结果筛选。每条记录展示：

- 操作对象；
- 变更前/变更后；
- 操作原因；
- 审批人；
- 生效版本；
- 成功或失败结果。

## 6. 门店经营配置模块

仅店长可维护当前门店。

### 6.1 门店资料

- 门店名称、地址、联系人、营业时间；
- 所属法人/财务主体；
- 是否参与跨店施工协作；
- 本店默认销售单位、默认施工地点；
- 业务负责人和通知接收人。

### 6.2 业务开关

将当前“快速开关”改为真实开关列表，每个开关包含：

- 开关名称；
- 业务影响说明；
- 当前状态；
- 生效范围；
- 修改后影响的页面；
- 最近变更记录。

初期可纳入：全过程照片、售后照片必填、客户短信提醒、低库存提醒、已派工筛选、发票完工限制等。没有后端接口的开关不显示。

### 6.3 通知偏好

店长选择本店的业务通知接收人和渠道；敏感密钥、OSS、SMTP 凭据仍由环境变量或总部管理员托管，页面只显示连通状态，不展示密文。

### 6.4 容量与预约默认值

独立维护到店、外出、玻璃膜、复检等施工容量及默认预约时段。保存后显示生效日期，不能与历史预约混用。

## 7. 财务结算配置模块

仅财务维护；店长可查看必要摘要，但不能编辑成本单价或结算口径。

### 7.1 岗位小时成本

- 生效日期、结束日期；
- 岗位与小时成本；
- 版本状态：草稿、已发布、已过期；
- 发布前校验岗位是否重复、成本是否为非负整数分；
- 已发布版本不可直接修改，只能新建版本。

### 7.2 成本与结算口径

明确配置：

- 实际入库价优先、缺失时材料成本标准兜底；
- 未结算订单允许因实际入库价补录刷新；
- 已完成成本结算订单永久冻结；
- 实际施工人工按确认工时计算；
- 提成按实际确认金额记录，不虚构未确认工时；
- 费用申请无金额阈值，店长单级审批，财务付款/入账；
- 已确认费用只能红冲或调整，不允许删除。

### 7.3 收款账户

账户新增、停用和默认账户切换应由财务操作，店长只读。已被收款记录引用的账户只能停用。

### 7.4 财务审计

集中查看收款、费用、成本、付款、红冲、改单审批和结算冻结记录。页面必须区分“查看”和“处理”按钮。

## 8. 权限模型

### 8.1 系统设置访问

| 能力 | 总部管理员 | 店长 | 财务 | 其他岗位 |
|---|---:|---:|---:|---:|
| 查看设置首页 | 是 | 是 | 是 | 仅显示相关入口 |
| 维护全局权限 | 是 | 否 | 否 | 否 |
| 维护总部字典模板 | 是 | 否 | 否 | 否 |
| 维护本店业务配置 | 否/按范围 | 是 | 否 | 否 |
| 维护岗位小时成本 | 否 | 否 | 是 | 否 |
| 维护收款账户 | 否 | 只读 | 是 | 否 |
| 查看审计 | 是 | 本店业务审计 | 本店财务域 | 否 |
| 发布全局配置 | 是 | 否 | 财务配置可发布 | 否 |

### 8.2 前后端一致性

- 前端菜单依据服务端能力列表生成；
- 后端每个写接口再次校验角色、门店范围和配置类型；
- 未授权操作不渲染按钮；通过 URL 直接访问时返回 403 页面，而不是空白页；
- 权限变更后刷新会话权限缓存；
- 页面显示“可查看/可编辑/需审批”三种能力状态。

## 9. 配置版本与发布流程

统一使用：

```text
草稿 → 校验中 → 待审批 → 已发布 → 已过期/已撤回
```

规则：

- 草稿只对创建人和有权限的审核人可见；
- 发布前执行字段完整性、重复冲突、引用关系和权限影响校验；
- 已发布配置不可原地修改；
- 新版本生效不回写历史订单、采购单、库存流水或财务记录；
- 每次发布生成版本号、生效时间和审计记录；
- 失败时保留草稿并展示具体字段错误。

## 10. 页面交互规范

- 所有分组标题后增加问号图标，悬停显示业务说明；
- 英文编码只作为辅助信息，主标题全部显示中文；
- 配置页面顶部固定显示当前角色、门店和生效版本；
- 保存按钮统一为“保存草稿”，发布按钮统一为“发布生效”；
- 危险操作必须二次确认并要求填写原因；
- 页面离开前检测未保存变更；
- 任何“测试连接”必须返回成功/失败详情和时间；
- 不使用“配置确认中”“审计已规划”等无动作状态，改为真实后端状态。

## 11. 现有页面到新页面的迁移

| 现有内容 | 新位置 | 处理方式 |
|---|---|---|
| 权限矩阵 | 总部治理 / 岗位与权限 | 从静态矩阵改为动作级权限编辑 |
| 基础字典配置 | 总部治理 / 基础字典模板 + 门店经营 / 门店字典 | 复用逐项启停与树形维护 |
| 门店配置占位卡 | 门店经营配置 | 接入真实接口后开放 |
| 快速开关 | 门店经营 / 业务开关 | 无后端能力的开关移除 |
| 账号设置跳转 | 账号与安全 | 区分个人资料、登录安全、成员管理 |
| OSS/SMTP | 门店经营 / 通知偏好 + 总部服务配置 | 密钥仍由环境托管 |
| 审计策略卡 | 总部治理 / 全局审计 | 显示真实日志与筛选 |
| 静态 KPI | 设置首页状态摘要 | 改为服务端实时统计 |

## 12. 实施阶段

### 阶段 0：清理与盘点

- 建立设置能力清单，标注已接通、部分接通、未实现；
- 删除或隐藏静态模拟开关和无动作按钮；
- 统一权限能力码和设置路由；
- 输出旧页面到新页面映射表。

### 阶段 1：设置首页与权限壳

- 新建角色工作台首页；
- 接入服务端能力列表、配置状态和待处理变更；
- 实现角色路由守卫、403 页面、未保存提示；
- 先迁移岗位与权限只读查看。

### 阶段 2：总部治理

- 动作级权限编辑和版本发布；
- 字典模板树形维护、逐项启停、并发版本控制；
- 安全策略与审计查询。

### 阶段 3：门店经营

- 门店资料；
- 业务开关；
- 通知偏好；
- 容量和预约默认值。

### 阶段 4：财务结算

- 岗位小时成本版本；
- 成本口径与结算冻结规则；
- 收款账户和财务审计。

### 阶段 5：迁移与回归

- 迁移旧配置和字典数据；
- 按总部管理员、店长、财务、销售、施工人员逐角色验收；
- 关闭旧的单页锚点入口；
- 发布操作手册和回滚方案。

## 13. 验收标准

### 页面验收

- 店长登录后只看到门店经营配置及允许查看的摘要；
- 财务登录后能进入财务结算配置，但看不到权限编辑和派工配置；
- 总部管理员能维护全局权限、字典模板和安全策略；
- 未授权用户不会看到可点击的维护按钮；
- 每个设置页面都有返回、保存草稿、发布（配置发布无审批；成本调整另行由财务审批）和审计入口。

### 数据验收

- 保存后刷新页面与服务端一致；
- 切换账号、门店、重新登录后权限和配置正确；
- 发布版本只影响生效时间之后的新业务；
- 历史单据快照不被配置变更改写；
- 任何失败操作不显示成功状态，且保留用户输入。

### 权限验收

- 前端隐藏与后端 403 同时生效；
- 店长无法修改岗位小时成本、总部权限和总部字典策略；
- 财务无法修改派工、施工容量、产品建议价和门店业务开关；
- 总部管理员的全局变更有审计记录和影响范围。

## 7.5 FinanceSettlement 实施补充（2026-07-29）

现有成本核算引擎继续负责计算，`finance.settlement` 负责版本化口径：

- `actualInboundPricePriority`：实际入库价优先；
- `standardMaterialFallback`：标准材料成本兜底；
- `missingCostPolicy`：实际成本缺失时禁止确认；
- `commissionSource`：使用财务维护的最终施工人员提成；
- `settlementFreezeAfter`：`SETTLED` 后冻结；
- `adjustmentPolicy`：成本调整仅财务审批。

迁移只生成每门店策略 v1，不回算历史订单；策略缺失时真实运行拒绝结算，避免隐式默认。
